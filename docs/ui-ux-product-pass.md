# OCI / VISION — компактный UI/UX-проход

## Задача и границы
Сделать основной путь «выбрать образ → запустить → понять результат → исправить» проще прямо в коде.
Основание: текущие TSX/CSS, не старые отчёты. Исходники не изменены; визуальная проверка браузером не проводилась.
Прочитан официальный Anthropic frontend-design/SKILL.md; новые пакеты, Figma и смена стиля не нужны.
Это blueprint реализации, не новая продуктовая спецификация. Сервер, API-клиенты, разрешения и автоматизацию не менять.

## Направление: узнаваемый A1, спокойный рабочий интерфейс
- Оставить OCI / VISION, выразительный главный заголовок и кислотные акценты; не превращать продукт в универсальный SaaS-dashboard.
- Палитра из текущего интерфейса: фон #141324, поверхность #211f34, текст #faf8ff, вторичный #ded9e9, действие #d1ff5e, дополнительный #a58aff. Home/auth сохраняют собственный тёмный фон #0b0c11.
- Сохранить Inter без загрузки шрифтов. Только главная использует крупную плакатную типографику; рабочие заголовки 28–40px, основной текст 15–16px/1.55, метаданные 12–13px. Текст до 70ch.
- Убрать повторные uppercase-надписи, декоративные номера и англоязычные служебные подписи из рабочих экранов. Номера оставить у реальных последовательных шагов.
- Один главный CTA на рабочий блок; кислотный цвет — действие/выбор, не обещание безопасности. Ошибки и неполнота — словами и иконкой, не только цветом.
- Не добавлять анимации и новые карточки ради декора. Брендовый hero остаётся на главной; история и отчёт начинаются с полезных действий.
- Самопроверка против шаблонности: сохраняем именно существующий A1; улучшаем плотность, тексты и порядок, не вводим новую дизайн-систему.

## Каркас
```text
Главная: бренд/навигация → характерный hero + две кнопки → 3 шага → возможности
История: компактная навигация → Мои проверки / Новая проверка → записи → Показать ещё
Создание: заголовок → репозиторий/версия → категории → подтверждение/запуск
Отчёт: образ/статус → результат + пробелы → действия → находки → подробности / ИИ
Аккаунт: email + переход к проверкам → безопасность → настройки отчётов
Чат: переписка → редактор + условия отправки → Решения / Данные и использование
```
Выравнивание рабочих экранов по левому краю; ширина текущего контейнера сохраняется. На мобильном одна колонка.

## P0 — не потерять правду и доступность
- Не менять `scanCheckSnapshot`, owner/session/report-version/cursor guards, отмену, источники, ключи запросов и обработчики POST.
- Неизвестно ≠ 0; выполнено ≠ безопасно; SBOM ≠ проверка уязвимостей; TEMP/DLA ≠ CVE. Не заменять на «всё хорошо».
- Неполноту, устаревшие данные, отказ доступа, блокировку отправки и неизвестный исход запроса показывать до закрытых подробностей.
- Оплата, провайдер, передача данных и существенная неопределённость хранения остаются рядом с действием. Нет согласия через открытие диалога.
- Не включать ИИ, не восстанавливать платный запрос и не повторять его автоматически. Существующее явное согласие на авторазбор сохранить без расширения.

## P1 — экраны и точные изменения
### Главная — `pages/home/HomePage.tsx` + `.css`
- Текущий hero уже объясняет продукт и даёт «Проверить образ» / «Пример отчёта»: сохранить обе кнопки и плакатный заголовок.
- Заменить надпись «ДИПЛОМНЫЙ ПРОЕКТ / OCI IMAGE SECURITY» на «Проверка контейнерных образов», без дополнительной плашки.
- Под кнопками: «Для запуска нужны вход и разрешение на проверку. Пример отчёта — вымышленные данные, без входа.» Ссылки входа/регистрации сохранить.
- В превью оставить одно явное «Иллюстрация, не результат проверки»; убрать повтор «КОНЦЕПТ · НЕ LIVE-ДАННЫЕ» и декоративные INSPECT/LOOK CLOSER.
- Сохранить существующие три шага и полезные вкладки; не добавлять ещё onboarding или модалку приветствия. Сократить повторяющие их подписи.

### История — `pages/scans/ScanListPage.tsx`, `features/scans/ScanShell.tsx`, `scan-a1.css`
- Использовать уже существующий `compact` shell, как create/detail. Убрать из списка крупную ScanScene и повторяющиеся chapter/folio/section-заголовки.
- Верхняя строка: «Мои проверки» + «Новая проверка». Под ней одна строка «Откройте отчёт или проверьте новую версию образа».
- Запись: название образа → один статус → имеющийся компактный прогресс → «Открыть отчёт». Убрать индекс и второе повторение статуса, не сам статус.
- Короткий ID оставить вторичными метаданными; полный ID/digest доступны в отчёте. Не заменять неполноту визуально успешным состоянием.
- Только подтверждённый пустой список: «Проверок пока нет» + кнопка «Проверить первый образ». Не показывать этот state при ошибке/отказе доступа.
- 403: «Проверки пока недоступны этому аккаунту. Вход выполнен, но запуск и история закрыты.» Ссылка «Открыть аккаунт»; не обещать ручную выдачу доступа или ID, которого экран не показывает.
- Ошибка без snapshot: «Не удалось загрузить проверки. Список пока неизвестен.» + «Повторить загрузку». При snapshot: «Новые данные не загружены. Показаны последние полученные проверки».
- Сохранить «Показать ещё» и логику страниц. «Обновить список сначала» → «Обновить список»; не добавлять клиентский поиск по неполному списку.

### Создание — `pages/scans/ScanCreatePage.tsx`
- Оставить существующий компактный экран и поиск репозиторий → тег, ручной ввод, результаты и управление фокусом. Не делать многошаговый wizard.
- Заголовок «Новая проверка»; вводная «Выберите публичный образ Docker Hub и нужные проверки». Коротко inline: «Linux amd64 · только публичные образы».
- Упорядочить видимые группы: «1. Образ», «2. Что проверить», «3. Подтверждение». Внутри выбора репозитория/тега использовать ненумерованные подзаголовки.
- Выбранная цель и актуальная доступность видны перед категориями. Успех допуска: «Выбранные проверки доступны. Перед запуском проверим ещё раз».
- «Проверить допуск снова» → «Проверить доступность снова»; сохранять ограничения повторов, таймер и неопределённость результата.
- Примеры старых образов свернуть в `details` «Тестовые образы»; внутри оставить предупреждение «Устаревшие версии — только для тестирования, не для рабочих приложений» и все пояснения о результатах.
- Ручной адрес и отдельный runtime-сценарий оставить в существующих `details`: это необязательные ветки, не причины для новых модальных форм.
- Короткая правая памятка: «Получите находки, состав образа и следующие шаги. Пустой результат не гарантирует безопасность». Подробные лимиты — диалог ниже.
- Убрать повторную нижнюю тройку «ЦЕЛЬ / ОБЛАСТЬ / РАЗРЕШЕНИЕ»: шаги уже есть в форме. Не убирать итоговое подтверждение цели/категорий.
- Рядом с заблокированной кнопкой оставить конкретную причину из текущего состояния: цель не выбрана / проверяем доступность / подтвердите выбор / ожидание / демо без запуска.

### Отчёт — `pages/scans/ScanDetailPage.tsx`
- Уже есть честный `ScanReportOverview`, переходы к находкам, coverage disclosure, фильтр и подтверждение отмены: сохранить, не переписывать.
- «Загружаем снимок…» → «Загружаем отчёт…»; «Повторить получение статуса» → «Обновить статус». Не терять отличие последнего снимка от текущего результата.
- Недоступный экран: «Войдите, чтобы открыть доступный вам отчёт». Ссылка входа не подтверждает доступ к чужому scanId.
- В кратком итоге всегда видны статус, известные количества/неизвестность, неполнота и ссылка «Что осталось непроверенным»; таблицу причин оставить раскрываемой inline.
- Из `statusDetails` вынести только точный образ/идентификаторы в «Данные проверки». Не переносить туда отмену, ошибку отмены, активный прогресс и предупреждение об отменённой проверке.
- Заголовки coverage использовать через существующий `scanCheckLabels`, не показывать пользователю сырые `secret/vuln/config` вместо названий.
- Исправления/источники, страницы CVE и нынешний ИИ-разбор остаются в отчёте. Не прятать важные ограничения ИИ-контекста или квоту за общим «Подробнее».

### Аккаунт и вход — `pages/auth/DemoAuthPage.tsx` + `demo-auth.css`
- Аккаунт уже содержит owner-scoped security/preferences и защиту при перепроверке: не перестраивать формы и их focus lifecycle.
- Оставить email, «Проверить образ», «Мои проверки»; компактнее заголовок/отступы, без повторного «ЛИЧНЫЙ КАБИНЕТ».
- Логин/регистрация: убрать «ДОСТУП / СТЕНДОВЫЙ РЕЖИМ» и номера «01/02»; оставить прямые заголовки «Вход» / «Создать аккаунт».
- Вводная: «Войдите, чтобы открыть свои проверки. Для запуска требуется отдельное разрешение». Демо — вторичная ссылка «Посмотреть пример без входа».
- Не убирать последствия смены пароля/выхода везде и одноразовое подтверждение; дополнительных модалок здесь не нужно.
- Текущие ошибки/перепроверка/paused остаются явными. Не объявлять выход при ошибке и не показывать данные прежнего владельца.

### Чат — `features/scans/ScanChatPanel.tsx` + `scan-chat-widget.css`
- Уже есть bubbles, skeleton, иконка отправки и preload: сохранить. Не переписывать Widget, BlockNote, Escape/focus/source-navigation.
- Главный объём окна — переписка. Вместо длинного нижнего общего disclosure — две компактные зоны «Решения» (`details`) и кнопка «Данные и использование» (диалог).
- Решения и их форма остаются в существующем `ChatScope`; не делать новый редактор/хранилище и не смешивать решение пользователя с выводом сканера.
- Inline у отправки: «Платный запрос через {provider}. Передадим вопрос, историю и контекст отчёта». Для unknown retention добавить «Хранение и обучение не подтверждены»; остальные режимы передавать точно по disclosure.
- Бесплатный профиль не называть платным. Видимая краткая формулировка следует текущему provider/disclosure, без выдуманных цен.
- Исчерпанная квота/предупреждение о лимите/недоступный учёт — коротко рядом с редактором; точные счётчики доступны в диалоге. Не трактовать счётчик как разрешение отправки.
- Ошибка/прерванный ответ: «Ответ не получен. Автоповтора нет; расход мог быть учтён». «Подготовить повтор вопроса» сохранить именно подготовкой черновика.
- Частичный/failed/cancelled отчёт: сохранить короткую видимую заметку о сохранённых результатах и непроверенных областях.

## Модальные окна: три конкретные группы, одна небольшая обёртка
Новый `shared/ui/ScanInfoDialog.tsx` на установленном `@radix-ui/react-dialog`; без реестров, новых библиотек или изменения API.
1. Создание, «Ограничения проверки»: размер/слои/время/диск, границы config, отличие runtime, подробное пояснение необязательного ИИ. Ключевые ограничения и оплата у действий остаются inline.
2. Отчёт, «Данные проверки»: исходный адрес, полный digest/platform, scanId, этап и статус из существующего блока. При отсутствии писать «Ещё не подтверждено», не обещать точную сборку.
3. Чат, «Данные и использование»: scan/report binding, epoch/revision/policy, полные provider/retention условия, readiness-техника, окна/токены/резерв/перенос/стоимость и последний receipt. Решения — отдельно.
Обёртка: Trigger asChild, Title, Description, видимая кнопка «Закрыть», Overlay, Portal; Radix управляет trap/Escape/возвратом фокуса. Открытие — без запросов.
Портал должен сам получить A1-класс: CSS родителя страницы в body не наследуется. Overlay z=80/content z=90 выше нынешнего чата z=60; не менять глобальный z-index вслепую.
Не переносить `ChatScope`, формы создания или guarded query-компоненты внутрь условно монтируемого диалога. Данные читаются из текущего scope; при потере доступа окно закрывается вместе с ним.
Сохранить рабочие aria-describedby: подсказки редактора должны существовать и при закрытом диалоге. В диалог переносить дополнительные данные, не единственную подсказку/причину блокировки.

## Объём и приёмка
Цель: 12 production-файлов — HomePage.tsx/.css; ScanShell.tsx; scan-a1.css; ScanListPage.tsx; ScanCreatePage.tsx; ScanDetailPage.tsx; новый ScanInfoDialog.tsx; ScanChatPanel.tsx; scan-chat-widget.css; DemoAuthPage.tsx; demo-auth.css. До 2 прицельных UI-test файлов: всего 14, без архитектурного рефакторинга.
Сначала compact history + правки текста/порядка; затем три диалога и чат; затем auth/mobile polish. Если тесно по времени — сохранять существующие secondary disclosures, не трогать guarded потоки.
- 360/390px и desktop: нет горизонтального скролла, длинные digest переносятся, кнопки/поля доступны, диалог max-height с прокруткой и safe-area, редактор не перекрыт клавиатурой.
- Кнопки не меньше 44px, чёткий focus-visible. Не терять reduced-motion, доступные названия icon-buttons и клавиатурную навигацию.
- Проверить Tab/Shift+Tab/Escape/возврат фокуса каждого диалога; отдельно Escape меню BlockNote и переход из чата к источнику.
- Проверить empty/loading/error/403/stale/partial/cancelled/unknown-count/paid/quota-blocked; реальные provider-вызовы не нужны.
- Достаточно typecheck и прицельных затронутых UI-тестов; не запускать полные серверные наборы. Скриншоты desktop/mobile делает parent, не выдавать source-review за визуальное доказательство.
Риски: CSS порталов и слои над чатом; dangling aria-describedby; потеря owner/focus при смене сессии; случайное сокрытие consent/неопределённости. Все устраняются локальными UI-правками без изменения бизнес-логики.
