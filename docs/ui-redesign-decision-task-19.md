## Компонентная карта и визуальный язык

- **Shell:** спокойная операторская консоль, явная навигация и постоянно видимое различие demo/live. Нейтральные светлые поверхности, основной текст `slate-950/700`, ограниченный indigo для ссылки/фокуса/CTA, amber для неполноты и маркировки demo, red для ошибок. Никакого зелёного маркера «безопасно» только потому, что проверка получила `checked`. Семантические тексты статусов обязательны независимо от цвета.
- **Список:** при доступном авторизованном API — карточки Card с кликабельным заголовком цели, текстовым Badge состояния, отдельным текстом стадии и процента; `percent=null` означает «прогресс неизвестен». Когда списка нет в API, показать «список недоступен», а не пустой результат. Демо-карточки отмечены как вымышленные. Не делать всю Card вложенной интерактивной областью с конфликтующими ссылками.
- **Запуск:** Card с постоянно видимыми ограничениями цели/scope/checks, нативными `label`, `fieldset`, checkbox согласия и понятным disabled CTA до появления browser ingress/identity. На desktop допустимы основная форма и соседняя панель ограничений; на mobile это одна колонка. Sheet не использовать для скрытия формы или подтверждения scope. Квитанция POST 202 не подтверждает pinned digest/platform.
- **Деталь:** в верхней части — цель, отдельно статус/этап и coverage каждого класса в обычном HTML; ниже — фильтр и находки с понятными пустыми состояниями. Текстовые Badge отдельно показывают состояние скана `partial` и исходы проверок `failed`, `unsupported`, `not_authorized`, `skipped` без ложного «0 CVE». Фильтр текущей страницы не равен глобальному отсутствию результатов. На mobile — существующий Radix Dialog в виде боковой панели для фильтра, с focus trap/restore; будущий shadcn Sheet ещё не установлен; coverage, ошибки, действия и находки остаются вне закрытого Sheet. Отмена и live SSE не имитируются до серверного контракта.
- **Размеры и типографика как дизайн-направление, не измеренный UI:** Inter с system fallback, базовый текст 16px, заголовки порядка 28–32px, отступы 4/8/16/24px, умеренные радиусы около 12px. Desktop ограничить шириной около 1120px, mobile при 375px и 320px — одна колонка, интерактивные области целиться от 44px, длинный digest переносить (`overflow-wrap: anywhere`), не скрывать текст горизонтальным scroll. Точные токены, контраст и метрики определяются и проверяются в `DIP-TASK-21…23`.

## Условия передачи в реализацию

1. `DIP-TASK-20` согласует `DIP-DOC-2` v2 и `docs/TZ.md` с новым дизайн-выбором и разрешением на другие shadcn-based источники; полные устаревшие дельты `DIP-TASK-9/12` не являются доказательством установки. Этот документ не меняет существующее наблюдаемое поведение.
2. `DIP-TASK-21` перед копированием pin конкретного Radix-variant registry JSON/коммита и SHA-256, проверка peer/transitive зависимостей и notices; адаптация локальных токенов без бесконтрольных CSS reset, не смешивать варианты Base UI и Radix в одном primitive. Текущее `src/app/styles/index.css` задаёт `color-scheme: light dark` без полной тёмной палитры: либо явно согласовать светлую тему, либо измерить контраст и нативные controls в системной тёмной.
3. `DIP-TASK-22/23` проверяют React 19/Tailwind 4/Vite 7 в реальном build, keyboard/focus/контраст (включая zoom и 320/375px), reduced-motion, bundle diff и screen reader **вручную**; Playwright на fixture не доказывает live API и работу настоящего SR. Публиковать только прошедшие результаты. Без защищённого browser ingress, разрешённых list/cancel, live SSE и CVE/SBOM результаты остаются fixture/partial, независимо от внешнего вида.

Ни один новый UI-компонент, зависимость или CSS в рамках `DIP-TASK-19` не установлен; размеры и цвета выше — решение дизайна для дальнейшей реализации, не результат инструментальной проверки.
