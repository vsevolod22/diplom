### Important identity boundary

`parseVulnFindings` accepts a remote `library/alpine` report or an exact currently accepted nginx archive binding. A new local inventory archive is neither. The runner first verifies native config digest/diffID/architecture against its generated bytes, then asserts that **the untouched local report is rejected** by the ordinary parser.

For the subsequent parser/storage/API tests only, it clones that real report and changes exactly **`ArtifactName` and `Metadata.RepoDigests`** to an explicitly synthetic Alpine-shaped identity, using the local archive hash as a test identifier. The finding data is unchanged. That identifier is **not a remote manifest digest**. No nginx receipt is forged, no production validator is bypassed/changed, and this projection does **not** establish remote or archive identity qualification. The separately labelled conflict derivative also modifies one finding to exercise hostile text/conflicting-source handling.

The raw positive Secrets report can go directly through its existing data normalizer. Both kinds of normalized result are published through the actual ledger `finishCombined`, followed by actual HTTP reads. This is stronger than parser-only fabricated JSON but deliberately narrower than a production scan end-to-end.

### Почему остановка до acquisition, а не ещё один projected «успех»

Проверены текущие `inflateLayer`, `LayerTarValidator`, `ArchiveAttemptBudget`, `archive-identity.ts`, `parseVulnFindings`, EOL-ветка `archive-scan-worker.ts` и result contract.

1. **Низкоуровневая bounded acquisition выглядит реализуемой в отдельном qualification-only script**, поскольку descriptors проходят compressed caps. Можно использовать generic `inflateLayer` + общий tar budget и `ArchiveAttemptBudget`, без вызова `prepareNginxArchive`, без nginx receipt и без host extraction. Но успех не гарантирован: optional gzip headers, tar extensions, один слишком большой файл, expanded size или scratch/time могут честно остановить попытку.
2. **Exact receipt блокирует текущий pipeline.** `validArchiveBinding` ищет target только среди `NGINX_ARCHIVE_CANDIDATES`; `finishArchive` также требует exact nginx target. `parseVulnFindings` без binding ждёт ordinary Alpine identity, с binding вызывает этот exact validator. Поэтому Node нельзя выдать за nginx, исправить `ArtifactName`/`RepoDigests` и назвать remote acceptance. Existing npm/source normalizers уже есть; это не отсутствие npm parsing.
3. **EOL/npm outcome нельзя честно протащить через текущую EOL-ветку без отдельного решения.** `archive-scan-worker.ts:128–131` при `OS.EOSL=true` выставляет `node: unsupported/NODE_INVENTORY_ABSENT`, не проверяя Node inventory. `archive-result-contract.ts:38–41` требует именно эту пару для unsupported результата. Если реальный Node12 report содержит npm inventory/положительные CVEs, «inventory absent» будет неверным утверждением; а вся EOL CVE-ветка не публикует findings. Это конкретный conditional integration blocker, **не обнаруженный native результат этого кандидата**. Код не изменялся.

По условию пользователя при оставшихся EOL/receipt blockers выполнена **остановка**: config/layers не скачивались, generic acquisition не запускалась, Docker не вызывался, DB/keys/Env не читались. Соответственно `allCapsVerified:false`, `scannerAttempted:false`; remote-origin positive report пока отсутствует.
