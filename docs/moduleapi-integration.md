## Non-negotiable accounting and response behavior

- Preserve the **same durable ledger, subject identity and four stores/JWT**. `quota-policy.ts:quotaPolicyFromEnvironment/checkedQuotaMonetaryPolicy` supports `LLM_QUOTA_LIFETIME_USER_COST_MICROS=5000000` with `LLM_QUOTA_MONETARY_LIMIT=uncapped`; here `uncapped` means no daily/request monetary cap, **not absence of the separate $5 lifetime cap**. Technical request/token/time/storage bounds remain finite.
- `QuotaLedger.lifetimeBudget()` sums settled cost plus `reserved/dispatched/fault` cost by `user_key`, with **no provider/policy/window/scan filter**. `reserveAttempt()` admits under the write transaction; cleanup deletes only old released zero-cost rows. Extend paid-context handling without splitting the ledger, rekeying accounts, changing old `quota_policy.paidAccounting`, resetting spend or dropping UNKNOWN holds. Preserve cross-provider concurrency, restart/rollover and exactly-once receipts. Current historical totals cover retained rows; do not claim recovery of records already deleted by older code.
- Current `estimateOpenAiCost` uses integer microUSD rates and one BigInt ceiling; those OpenAI rates are **not** ModuleAPI rates. Establish an explicitly reviewed conservative billing/reservation contract for the effective group before enabling generation. Unknown subscription conversion/fees cannot be silently treated as USD0 or a proven hard provider-invoice cap. If a safe reserve cannot be established, generation stays blocked despite deployment authorization.
- Preserve one immutable sanitized payload for sizing/reserve/send, final synchronous owner/session/consent/report fence, dispatch-before-send, receipt before output validation, durable commit before JSON/NDJSON success. Unknown usage, timeout, aborted/failed send or rejected response retains liability; no repair, posttranslation, automatic retry or provider fallback. Validate `x-moduleapi-cost` units/grammar/bounds/provenance if supported; never directly trust it as settlement authority.
- Existing request fields include `max_completion_tokens`, `reasoning_effort:'none'`, `n:1`, `stream:false`, `store:false`, `service_tier:'default'` and closed JSON Schema. Verify ModuleAPI accepts the exact intended subset; do not silently remove safety/schema requirements after rejection. Existing provider requires exact response model and bounded usage: define explicit accepted alias/returned-model semantics rather than accepting arbitrary receipts. `store:false` is a request option, not evidence of retention/no-training.
- Preserve Russian narrative, citation/source-card and exact report binding validation (`openai-response-contract.ts`, `response.ts`, `history-contract.ts`). Separate advisory translation remains OpenRouter (`translation.service.ts`, resolver `translationCompatible()`); do not silently reroute it or bypass its quota incompatibility.
