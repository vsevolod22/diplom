# DIP-TASK-27 — обзор трёх направлений UI сканов

**Статус:** дизайн-сравнение и рекомендации к обсуждению, **не согласование человеком и не production-реализация**. [Интерактивный preview](task-27-preview.html) — автономный HTML с собственными CSS-анимациями и JS-переключением экранов/фильтров, **не демонстрация импортированных Magic UI, Aceternity, Motion Primitives или Embla**. Preview демонстрирует собственное декоративное scroll-linked движение и отдельную необязательную ручную галерею иллюстраций для списка, формы и детали. Находки, результаты и покрытие всегда вне неё; это не реализация сторонней библиотеки и не принятый production-дизайн. Ни один из кандидатов этой записью не установлен и не допущен к импорту.

## База сравнения

[package.json](../../package.json) заявляет React/React DOM `^19.1.1`, TypeScript `~5.9.3`, Vite `^7.1.7`, Tailwind CSS `^4.1.15`, `@tailwindcss/vite`, Radix Accordion/Dialog, `motion` `^12.23.24`, `lucide-react`, `class-variance-authority`; [components.json](../../components.json) задаёт shadcn `new-york`, TSX, CSS variables и alias `@/shared/ui`. Это **манифест**, не свидетельство совместимости нового registry-кода. [TZ.md](../TZ.md) (§ «Интерфейс сканирования», «Устойчивый доступный UI», «Дополнительные UI-компоненты») и [решение DIP-TASK-19](../ui-redesign-decision-task-19.md) требуют текста для state/stage/reason/coverage, отличия demo от live, несокрытия важных данных за эффектом/Sheet и деградации движения; одобрение прежней композиции Card/Badge/Sheet не означает одобрения нового дизайна или установку Sheet.

**Одинаковый набор данных для A/B/C и всех ширин:** `/demo/scans` — явно фиктивные записи: одна `running` с `percent=null` и строкой «прогресс неизвестен», одна `partial` с coverage `failed` и `unsupported` и отдельными текстовыми причинами. `/demo/scans/new` — scope, чекбокс согласия, ограничения и неактивное действие, пока условия не выполнены; ответ POST 202 не доказывает digest/platform. `/demo/scans/:id` — те же target/state/stage, coverage и reasons, находки и фильтр «нет совпадений» со сбросом, отдельное «0 findings» только при подтверждённом результате и отдельно «не проверено» при неизвестном/failed coverage. `/scans` — «защищённый browser ingress и список недоступны», **не** «список пуст». Никаких заявлений о работающих cancel/SSE/CVE/SBOM. На 320/375 px — одна колонка, длинный digest переносится, содержимое и действия не зависят от hover; на 1280 px — расширенная композиция с тем же содержимым и порядком чтения. Содержимое сценария отображается в автономном preview; его фактическая доступность в production не следует из макета.

## Матрица решений

| Критерий | A — Редакционный маршрут | B — Карта покрытий | C — Типографический журнал |
|---|---|---|---|
| Выразительность / композиция | Крупные заголовки, главы 01–03, асимметрия на 1280; тёмный графит с лаймовым и фиолетовым акцентами; sans + моно для digest | Плиты с подписями результата и причины, не цветовая теплокарта; светлая сетка, зелёные акценты; янтарный для неполноты, красный для отказа; плотные числовые метки | Колонки как рубрики, якорное оглавление и журнал событий; бумага/тёмные чернила, терракотовый акцент; контраст display-текста и моно-метаданных |
| State → coverage → findings | Глава «Состояние» перед главой «Покрытие», затем находки; на мобильном сохранять эту последовательность | State сверху, далее плитки coverage с `failed`/`unsupported` и reason всегда в теле, затем находки; композиция не должна превращать `checked` в «безопасно» | Статус/этап в шапке выпуска, coverage в оглавлении и секции отчёта, находки ниже; якоря не заменяют видимые причины |
| 320/375 → 1280 | Номерные главы в одну колонку → асимметричная двухколоночная сетка; длинный digest переносится | Одна плита на строку → неодинаковые плитки, но одинаковый DOM/порядок; не скрывать плитки за каруселью | Одна последовательность рубрик → поле оглавления и статья; оглавление не перекрывает управление |
| Motion-first приоритет (фактически в preview) | Скролл двигает декоративный знак и прорисовывает линию глав; галерея необязательных типографских иллюстраций на list/create/detail управляется кнопками, не свайпом (Blur Fade/Embla только кандидаты) | Однократный декоративный штамп у плит при появлении и scroll-linked поворот орнамента галереи; выбор плиты не меняет исход; галерея с кнопками и счётчиком, не coverage (In View/Bento только кандидаты) | Скролл смещает бумажный угол/орнамент галереи, оглавление отмечает текущую рубрику; ручная галерея отдельно от статьи и находок (Sticky Scroll Reveal отклонён для текста) |
| Reduced motion / управление | Media query и ручной переключатель выключают декор без сокрытия глав; галерея: 3 кнопочных шага, без autoplay/loop, с граничными disabled-кнопками | Плиты всегда видны, штамп без анимации; причины вне галереи; кнопки и счётчик не зациклены | Текст и якоря всегда видны; без smooth scroll/scroll-jacking; галерея только необязательных иллюстраций; без JS — статичное уведомление об ограничении интерактивного preview |
| A11y / стоимость / риск | Риск скрыть текст при не сработавшем observer и сдвинуть фокус; дополнительная Embla-зависимость и проверка стрелок/таб-порядка | Риск принять reveal за ход сканирования и Bento за статус, риск hover-only CTA; монтаж observer и Embla требуют замера | Sticky с собственным scroll-контейнером и opacity неактивного текста может осложнить чтение, клавиатуру и мобильный порядок; вероятно выбрать более простое In View |

**Storyboard (одни данные на всех направлениях):** 1) `/demo/scans`: постоянный баннер «Демо · фикстуры», статичные строки `running / прогресс неизвестен`, `partial` и 0 находок у отдельно проверенных Secrets. При скролле A прорисовывает только линию и смещает знак, B ставит декоративный штамп/поворачивает орнамент, C смещает бумажный знак и отмечает рубрику. Ссылку на деталь имеет только partial-запись; у остальных явно указано, что отдельная деталь не представлена. 2) `/demo/scans/new`: scope, согласие, ограничения и disabled CTA всегда видны; только кнопки листают три *дополнительные иллюстрации*, не форму. 3) `/demo/scans/:id`: state/stage и `failed`/`unsupported` + reasons видны вне галереи, как и находка/«нет совпадений»/сброс; иллюстрации не содержат результатов. 4) `/scans`: честная недоступность live, без анимации ожидания ответа и без галереи. 5) при `prefers-reduced-motion: reduce` либо ручном отключении декор останавливается без сокрытия текста, оглавление продолжает показывать текущую рубрику. Галерея листается только кнопками, без swipe/autoplay/loop; без JS вместо экранов выводится честное статичное уведомление, полные макеты без JS недоступны. Ни registry-интеграция, ни React-runtime этим HTML не проверены. Анимация не означает live-прогресс сканера.

## Проверка изолированного preview (Playwright Chromium, 2026-09-28)

Проверен локальный `file://` HTML, **не** production React и не screen reader. Скрипт через установленный `@playwright/test` (без добавления файлов/зависимостей) открыл A/B/C × list/create/detail/unavailable × 320/375/1280 = **36 случаев**. В каждом: есть заголовок, нет горизонтального переполнения `documentElement`, gallery только на трёх demo-экранах с ровно одной активной иллюстрацией; Enter по кнопке переводит счётчик на 2/3, ручное отключение добавляет `motion-off`. На каждом list — ровно одна ссылка на частичную деталь, running и 0-findings не притворяются ею. На каждом detail фильтр CVE выводит «неизвестно», а не ноль. Ошибок страницы не зафиксировано; тест завершился без ошибок.

Отдельно: при эмуляции `prefers-reduced-motion: reduce` B/detail остались видимы все 5 плит, движение отключено; изменение системной настройки обратно на `no-preference` сняло отключение (observer заново инициализируется). В C/detail при 320 px нативный якорь coverage сохранил hash, Tab назад после Enter по слайдеру переместил фокус на «Предыдущая», длинная прокрутка не вызвала overflow; переход partial из A/list в A/detail переместил фокус на main. С выключенным JavaScript отображается статичное уведомление вместо пустого экрана. **Не проверены** настоящий screen reader, touch/swipe (не реализован), профилирование FPS/jank и runtime/лицензии registry-кандидатов. Текущая галерея кнопочная: Embla/swipe не заявлены.
