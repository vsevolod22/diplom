## Что делает эта реализация

- Actual free-only `LlmService → OpenRouterProvider` использует один `PreparedRequest`: полный immutable JSON wire string, SHA256, input reserve `Buffer.byteLength(B,'utf8')+1024`, output=current `policy.outputTokens≤2048`, estimate=0. Transport получает тот же B. Byte bound — консервативная продуктовая оценка фиксированного tool-free producer, не measured tokenizer или billing proof; bounded observed overruns сохраняются и блокируют admission.
- Quota runtime default-off. Не настроенная/invalid/enabled-but-storage-unavailable политика запрещает реальную free-only генерацию. Трёхаргументные fake providers и отдельно настроенный legacy adapter сохраняют прежний контракт; их успех **не доказывает production quotas** и не разрешает платную активацию.
- Новый отдельный `/auth/llm-usage.sqlite`, только существующий API-only auth volume. Никакой миграции текущих `auth.sqlite`/`ledger.sqlite`, доступа worker или новой volume/resource/network/key границы.
- Один immutable attempt row влияет на user и subject+scan scopes; insert/CAS одной SQLite transaction даёт атомарность обеих scopes. В DB только hashes identity/scan, report/policy/request hashes, non-secret quota policy snapshot, original UTC window, finite receipt expiry, reserves/effective vectors, phase и receipt digest. Нет prompts, summary/history, cookies, provider key, raw responses или клиентского settlement endpoint.
- `BEGIN IMMEDIATE` перед clock sample, durable clock high-water, 24h UTC calendar windows. Политика/revision/report/session не создают новые namespace counters. Старые reserved/dispatched/fault liabilities один раз carried в новое headroom; terminal historical charges естественно выходят из активного дня, не считаются refund.
- CAS `reserved→dispatched` durable **до transport handoff**. CAS `reserved→released` запрещает delayed sender dispatch. `dispatched` не refund от timeout/cancel/TLS/gateway/crash/restart/TTL. Conservative false debit marker-before-send намеренно принят. Recovery допускает `release` только known internal reserved IDs; автоматического resend или destructive recovery нет.
- Normal receipt: explicit finite safe integer prompt/completion, optional total consistent, exact model, cost=0 и counts≤reserve; atomic replacement actual/releases. Invalid finish/content/citations, stale report/access/consent/policy и browser lifetime не отменяют accounting.
- Incomplete/invalid dimensions не release. Independently bounded known dimensions сохраняют `max(reserve,known floor)` и durable `fault`, blocking обе затронутые scopes до безопасного operator resolution. Missing/nonfinite/unbounded numbers не превращаются в ноль. Positive reported cost — fault, не разрешение paid mode и не invoice proof. Нет автоматического fault reset API.
- Срок bound receipt — admission+300000ms (можно явно выбрать 30000..300000); после него liability сохраняется. Terminal replay horizon — 7 дней после original window end. Identical terminal receipt no-op; conflicting не переписывает. Проверенный internal late receipt может settle после service timeout без публикации/второго call. Transport после abort не дренируется ради неизвестного usage; невалидированный/недоступный receipt остаётся unknown.
- `GET /api/v1/browser/scans/:scanId/llm/usage` — отдельный cookie/owner/report-auth/no-store маршрут, без generation consent/enablement, reserve/model calls. Foreign/missing одинаково hidden. Explicit integration/quota/availability flags, UTC window, used/held/carried/remaining, safe scope/dimension signals. `admission` отдельно показывает `fits/insufficient/policy_fault/unavailable`: server-only shared `prepareSummary` определяет полный current free-only envelope без provider/key/consent/reserve. Невозможный candidate (disabled/non-free policy, нет evidence, context/producer/request-input bound) означает unavailable, не readiness. Ledger проверяет один и тот же reserve vector и в read-only snapshot, и под admission write lock; положительный remaining ниже required даёт scope/dimension/required/remaining. `reason` counters остаётся числовым threshold snapshot, не обещанием следующего вызова; UI при insufficient не показывает ready. POST429 включает только factory-branded `admission`, не произвольное тело HttpException, internal IDs или diagnostics. Quota stats **не добавлены** в context DTO, `policyVersion`, consent или `contextFence`; счётчики не создают ложную stale generation.
- UI только `ScanSummaryPanel`, новый `LlmUsagePanel` и `llmUsageClient`. Пользователь открывает счётчики кнопкой «Обновить остаток ИИ»; после этого focus/summary completion обновляют только GET. До чтения/при ошибке остаток неизвестен, не ноль. Strict 16KiB JSON/15s bounded client, tuple+session-generation checks, ordinary escaped DOM text, abort/clear при изменении session/scan/report/access. Findings/coverage не зависят от usage. Не менялись `llmSummaryClient`, pages/scans, Scene, GlowEffect и CSS peers.

## Конечные storage safeguards

`better-sqlite3` уже был зависимостью; новой зависимости нет. Production открывает только уже инициализированный файл: missing/empty/wrong-schema файл fail-closed, startup/recovery не создаёт и не пересоздаёт tables. Явный bootstrap `quota-init.ts --initialize` только для оператора после approvals/backups; он отказывается от существующего файла и не запускается этим автором. Disposable fixtures явно включают отдельный initialize mode. Own application ID/schema v1 guard, filename `llm-usage.sqlite`, regular non-symlink/single-link/current-UID owner0600 file, canonical parent path; foreign schema и corrupt SQLite не ремонтируются. `page_size=4096`, `max_page_count≤16384` (64MiB logical), `synchronous=FULL`, rollback `journal_mode=DELETE`, `journal_size_limit=0`, `temp_store=MEMORY`, cache 2MiB/connection. Нет unbounded WAL/checkpoint growth. Максимум 100000 metadata rows включая singleton; maintenance delete≤256 terminal rows/transaction только после replay horizon; unknown/fault никогда не удаляются ради headroom. Политика меняется не чаще четырёх live versions за process lifetime: old handles сохранены для original receipts, затем fail-closed/restart под контролем оператора.

Admission проверяет DB pages, rows, sidecars и свободное место до/после собственной write transaction, rollback при нарушении. Минимум свободного диска 128MiB (верх выбора256MiB), finite lock wait≤1000ms. Rollback journal ограничен touched pages исходного bounded DB плюс finite header slack≤1MiB. Это **не hard shared-volume physical guarantee**: внешние auth writers и disk failures могут исчерпать диск после проверки. Commit/settlement failure не публикует success и не стирает prior durable reserve. New generation без безопасного доступа к storage fail-closed; zero actual сохранённым не объявляется. При storage fault write с overage может не сохраниться: остаётся прежний conservative reserve, known floor не заявляется durable до успешного accounting retry; автоматического provider retry нет.

Input/output arithmetic scope caps≤1e9; separately bounded observations≤1048576 tokens/dimension. Cost — точные micro-USD, только числа с ≤6 десятичными знаками, observation≤1USD. Никакого округления вниз или NaN/Infinity. Capacity/receipt/clock нарушения и metadata full могут запрещать генерацию неограниченно долго — это безопаснее неизвестного refund.

## Operator activation — отдельное решение родителя

`server/deploy/compose.stand.openrouter.free.yaml` остаётся **тем же четвёртым fixed LOCAL overlay**, без пятого profile/descriptor, смены locks/refresh/rollback, volumes/resources/networks/private key mounts. Только API nonsecret quota env добавлен. Default `LLM_QUOTA_ENABLED=false`, caps отсутствуют и enabled при этом fail-closed; revision=undecided также invalid. `server/deploy/llm-quota.opt-in.example` — неактивный non-secret пример с обоими approvals OFF. Parent **выбирает caps перед deploy**. Исполняемая staging граница описана ниже; bootstrap не выполнялся здесь и не является runtime activation. Отсутствующий quota file не автоматически bootstrap, иначе потеря DB могла бы сбросить расход. Нельзя удалять/создавать существующий ledger ради headroom. Judge baseline user262144/16384, scan65536/8192, USD0/0, warning80%. Missing values runtime не подставляет. Этот автор ничего не активировал/развернул, не читал private env/key, не делал LIVE/provider/model/docker/account writes и не коммитил.

Текущий LOCAL после обновления кода и без явной полной quota activation безопасно откажет **реальной free-only summary**, даже если LLM policy включена. Read-only context по-прежнему показывает только существующую nonsecret LLM policy readiness, не подтверждает quota/key/provider readiness; отдельный usage показывает quota status. Это намеренный fail-closed impact, который parent должен проверить перед deploy. Legacy/disabled/mocks regression compatibility не является разрешением реального legacy paid вызова.

### Staging: quota-only bootstrap, затем отдельная runtime activation

1. До действий parent принимает supplemental reviews, утверждает конечные caps и recovery/backup план; сохраняет consistent online backups, старые image identities, JWT/accounts/scans. Existing shared lock и frozen four-file selection остаются прежними. Не запускать общий deploy helper, который сразу builds+ups, как bootstrap; не делать stand:auth, down-v, prune/reset или добавлять пятый overlay.
2. Под существующим operator workflow **build-only** подготовить новую reviewed API image из принятого source/hash, не обновляя LIVE services. Старый работающий API не bind-mount checkout: наличие изменённого файла в репозитории не означает его наличие в старом container. Parent проверяет immutable image/source identity и наличие `src/llm/quota-init.ts`, установленного `tsx` и SQLite dependency именно в новом образе; не fetch/install пакеты как обход. Статический `server/deploy/api.Dockerfile` копирует source/dependencies, задаёт cwd `/app/server/api` и `USER 65532:65532`; доступность running image этим агентом не проверена.
3. Запустить **только initializer**, не Nest/main entrypoint, в изолированном operator-approved bootstrap process из этого reviewed image/source: cwd **`/app/server/api`**, UID/GID **`65532:65532`**, существующий canonical API-only auth mount **`/auth`**, image/source read-only, без ненужной сети/gateway/key/private env injection. Parent должен установить полную явно выбранную nonsecret quota policy в process environment, **`LLM_QUOTA_ENABLED=true` только для bootstrap**, **`LLM_ENABLED=false` и `LLM_ROUTING_APPROVED=false`**. Пример по умолчанию quota=false и без такой отдельной смены не инициализирует; Node не загружает пример или dotenv автоматически. Не использовать private key env-file как Compose interpolation.
4. Только при выполнении этих prerequisites команда из указанного cwd: `pnpm exec tsx src/llm/quota-init.ts --initialize` (либо image-native `node --import tsx src/llm/quota-init.ts --initialize`). Это не готовая Docker-команда: exact image/mount/lock выбирает и проверяет parent, не выдумывается автором. Инициализируется только **новый `/auth/llm-usage.sqlite`**, regular single-link non-symlink, owner UID65532, **mode0600**; текущие auth/scans DB не мигрируются. Нельзя host/root bootstrap с похожим filename или сменой владельца существующего исторического store. Existing file отвергается; lost/corrupt/schema-lost ledger — отдельное recovery решение, не удаление/пересоздание для нового allowance.
5. Parent privately проверяет initialized schema/owner/permissions/canonical mount, consistent backup quota вместе с recovery evidence и неизменность accounts/scans. Только затем **отдельно** принимает runtime enablement, передаёт полные approved caps в API process и делает controlled deployment/activation по прежнему lock/four-file workflow. Bootstrap quota=true не разрешает routing/generation=true. Key/API-only volume/worker/resources/gateway границы остаются прежними. Новый free-summary code без полной quota policy + безопасного existing initialized store намеренно fail-closed даже при ранее включённой LLM policy.

Ни initializer, ни build/deploy/Docker, ни runtime enablement автором не запускались. Политика хранения/unknown liabilities не reset ради deploy.
